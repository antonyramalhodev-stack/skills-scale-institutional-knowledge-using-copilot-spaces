# OctoAcme Project Management Processes

Welcome to OctoAcme’s project management documentation hub. These guides describe a structured, lifecycle-based approach to delivering customer value through iterative work, clear ownership, evidence-based decisions, and continuous learning.

Projects move through five phases: **Initiation** validates the business need and stakeholder alignment with a Project One-pager; **Planning** turns approved work into a prioritized, estimated backlog with clear acceptance criteria; **Execution** tracks delivery on a project board and keeps teams aligned through daily standups, weekly syncs, and sprint planning; **Release** uses pre-release checks and incident playbooks to deploy safely; and **Retrospective** captures lessons and tracks improvements.

Quality is built in throughout delivery with automated tests, CI/CD security scanning, and manual QA. Project Managers coordinate schedules, risks, and communication; Product Managers set priorities and measure outcomes; Developers build and test solutions; and QA/Testing validates acceptance criteria. Communication includes weekly PM–Product Manager alignment and monthly stakeholder updates. The overview describes twice-weekly standups, while the execution guide recommends daily standups. Retrospectives and metric tracking help teams improve continuously.

## Project lifecycle

Use these guides in phase order, or jump directly to the process you need:

1. **[Initiation](octoacme-project-initiation.md)** — Validate the business need, define outcomes and success measures, align stakeholders, and get approval to plan.
2. **[Planning](octoacme-project-planning.md)** — Break approved work into prioritized, estimated backlog items with acceptance criteria, dependencies, and a Definition of Done.
3. **[Execution & Tracking](octoacme-execution-and-tracking.md)** — Deliver iteratively using a project board, team rhythms, quality checks, metrics, and blocker escalation.
4. **[Release & Deployment](octoacme-release-and-deployment.md)** — Confirm release readiness, deploy and verify, and follow rollback and incident guidance when needed.
5. **[Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md)** — Review outcomes, agree on owned action items, and use metrics and learnings to improve future work.

## How to use these docs

- **New to OctoAcme?** Start with the [overview](octoacme-project-management-overview.md), then read [roles and personas](octoacme-roles-and-personas.md) to understand ownership.
- **Starting a project?** Work through [Initiation](octoacme-project-initiation.md) and [Planning](octoacme-project-planning.md) before delivery begins.
- **Managing active work?** Use [Execution & Tracking](octoacme-execution-and-tracking.md) alongside [Risks & Communication](octoacme-risks-and-communication.md).
- **Preparing for a release?** Follow the [Release & Deployment](octoacme-release-and-deployment.md) guide and its pre-release checklist.
- **Closing a milestone or learning from an incident?** Run a [Retrospective](octoacme-retrospective-and-continuous-improvement.md) and track the resulting action items.
